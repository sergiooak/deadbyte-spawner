# Choosing a Nucleo Pixel icon

Adapted from the Supporte nuxt-layer skill. Icons are **Nucleo Pixel** (24px grid, 2px square-cap strokes), referenced by their official name: `<UIcon name="i-nucleo-robot" />`. The SVGs are used exactly as exported: never edit paths, stroke widths or caps.

**Brand logos are the exception.** A logo of a company or product (GitHub) comes from simple-icons: `<UIcon name="i-simple-icons-github" />`.

## Licensing

The repo is public and the Nucleo license does not allow publishing the catalog. The full export lives in `icons/nucleo-source.json` (git-ignored, copy it from the Nucleo app export). The committed `icons/nucleo.json` only holds the icons the panel uses, generated by `pnpm icons:build`.

## Steps

1. **Reuse first.** Run `node cli/nucleo.mjs map <concept>`. If the concept already has a decision, use that icon and stop.
2. **Name the meaning.** Write one sentence: what must this icon tell this user, in this place? Search in English from several angles (object, action, metaphor, state).
3. **Search.** `node cli/nucleo.mjs search <terms...>` or the `/dev/icons` page in `pnpm dev`.
4. **Judge.** Prefer specific over generic, readable at the rendered size, consistent with neighbours. Pixel icons are crispest at 24px or 12px; `shape-rendering: crispEdges` keeps other sizes sharp.
5. **See them.** `node cli/nucleo.mjs preview <candidates...> --context <neighbours>` writes a board in `.tmp/`.
6. **Record.** Add the decision to `icons/map.json` with `icon`, `alts` and `reason`.
7. **Bundle and check.** Write the name as a string literal in the code, then run `pnpm icons:build` and `pnpm icons:check`.

Done when the icon is a string literal in the code, the decision is in `icons/map.json`, `icons/nucleo.json` was rebuilt and `icons:check` is green.
